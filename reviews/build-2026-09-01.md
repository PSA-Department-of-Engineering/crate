## 1. Scope & Implementation Audit

### A. Electron Process Isolation & Security Boundary
- `electron/main.ts` enforces `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true`.
- `electron/preload.ts` exposes a clean typed `window.crateBridge` with explicit IPC handlers for library scanning, tag writing, volume discovery, delta sync analysis, and playlist export. Direct Node.js access is inaccessible to renderer code.

### B. Offline Zero-Telemetry Guarantee (`INT-TAG-006`, `REQ-TAG-003`)
- Verified `package.json` contains zero network telemetry or tracking packages (`@sentry/*`, `google-analytics`, `mixpanel`, etc.) and zero online metadata scraper dependencies (`musicbrainz-api`, `discogs-client`).
- All metadata indexing, tagging, and audio playback run strictly on the local filesystem without external API calls.

### C. Audio Metadata & Tag Preservation (`INT-TAG-001`, `INT-TAG-002`, `INT-TAG-005`)
- **MP3 (ID3v2)**: `AudioMetadataService.writeMp3Tags` reads existing tags via `NodeID3.read` and merges updates over existing frames, preserving untouched tags.
- **FLAC (Vorbis Comments)**: `AudioMetadataService.writeFlacTags` parses the native FLAC binary container, preserves the initial `STREAMINFO` block, updates/merges `VORBIS_COMMENT` entries without dropping existing fields, creates/updates `PICTURE` blocks (APIC), and preserves the trailing audio data stream bit-for-bit.
- Corrupted audio files are gracefully flagged and isolated without halting batch scanning (`INT-LIB-002`).

### D. Filesystem Layout & FAT32 Path Sanitization (`INT-ORG-001`, `INT-ORG-002`, `INT-ORG-003`)
- `sanitizeFat32Segment` strips forbidden FAT32/exFAT characters (`< > : " / \ | ? * \x00-\x1F`), trims trailing dots and whitespace, handles Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`), and provides fallback for empty segments.
- Formats files into `<Artist>/<Album>/<Track#> <Title>.<ext>` and multi-disc albums into `<Artist>/<Album>/Disc <N>/<Track#> <Title>.<ext>` matching automotive head unit layout expectations.

### E. Car Sync Delta Engine & Stale File Detection (`INT-SYNC-001` - `INT-SYNC-003`)
- `SyncManagerService.analyzeSync` accurately computes incremental transfer plans by evaluating destination existence, file size parity, and mtime timestamp differences within 2000ms (accounting for FAT32 2-second timestamp resolution).
- Supports sync scopes for entire library, selected playlists, or selected albums.
- `executeSync` applies `fs.promises.utimes` to preserve modification timestamps on the target drive and prunes stale audio files when requested.

### F. M3U Playlist Generation (`INT-PLST-001`, `INT-PLST-002`)
- `PlaylistExporterService.generateM3UContent` emits standard `#EXTM3U` and `#EXTINF` metadata headers with relative paths and strict `\r\n` (CRLF) line terminators for automotive firmware compatibility.

### G. Multi-Window Audio Player & Undocking (`INT-PLY-001` - `INT-PLY-004`)
- Implements frameless secondary player window loaded with `#undocked-player` via `UndockedMiniPlayer.tsx`.
- Bidirectional state and command broadcasting between main window and secondary window over IPC events (`player:state-change`, `player:state-sync`, `player:command`).

### H. Visual Identity Tokens & UI Aesthetics (`INT-UI-001`, `INT-DIST-001`, `INT-DIST-002`)
- Visual identity tokens in `src/index.css` and `tailwind.config.js` match `.delivery/design.md` and `docs/brand.md` (`--primary: 160 84% 39%`, `--background: 40 33% 97%`, `--radius: 0.75rem`, `Nunito` font stack).
- `WebFallbackView.tsx` provides honest prerequisite messaging explaining why desktop execution is required for local disk writes and presents direct portable executable downloads with SHA-256 verification and Windows SmartScreen guidance.
