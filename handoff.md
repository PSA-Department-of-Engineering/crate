# handoff.md - crate, one-shot autonomous delivery handoff

This is the complete handover for an autonomous implementation run. Every decision is pinned or pointed at its durable home, this run is authorized by the standing profile or per-run grant in §0, every external dependency has a pre-flight and a degraded stop-state, and any point that genuinely needs a human becomes a §10 degraded stop-state. If executing this handoff ever requires a decision not written or pointed to here, that is a handoff defect: make the smallest reasonable choice, record it in the final report under "plan defects", and continue. Do not stop to ask.

## 0. Mission, authorization, done-definition

**Mission.** Deliver Crate (Phase 1: Core Application & Car Sync), a Windows desktop application for managing personal music libraries (MP3 and FLAC), viewing/editing tags directly on disk (ID3v2 and Vorbis comments), structuring files according to car head unit expectations, authoring relative M3U playlists, playing audio with an undockable player, and synchronizing music and playlists incrementally to removable USB/SD drives. The verbatim ask and requirement IDs live in `.delivery/request.md` and `.delivery/proposal.md`.

**Gates already passed** (`REF-Delivery.md` §1): proposal accepted 2026-09-01 (recorded in `.delivery/proposal.md` and the estimation project `http://estimatekit.chaos-architect.dev/projects/crate`); design approved 2026-09-01 (recorded in `.delivery/design.md`); plan signed pending (this handoff).

**Authorization.** The operator pre-authorizes this run, under this per-run grant, to:

1. Push commits to `origin/main` and `origin/delivery/*` in repo `crate` (`d:/code-repos/crate`).
2. Interact with the Foundry platform studio MCP (`platform-studio-chaos` / `platform-studio-psa`) to onboard the web distribution app and create/manage onboarding pull requests.
3. Build portable Windows desktop releases and generate SHA-256 release checksum files.
4. Manage repository tags, issues, and milestone tracking.

When the done-definition requires the app live, executing §8 end to end - the first-release and onboarding sequence, including conforming the app repo to the §7 contract so the shared CI can release - is in-grant by this section without further enumeration: a done-definition the grant cannot reach is a contradiction this template does not permit, and a run discovering mid-flight that the pipeline was never wired finishes the wiring rather than stopping.

**Not authorized** (restate this list verbatim in the §13 kickoff prompt):
- Modifying repositories other than `crate` and the platform deployment PR generated by the onboarding studio.
- Deleting or overwriting user files outside the explicitly targeted library or removable sync directory.
- Introducing online metadata lookup dependencies, telemetry services, or cloud analytics (strictly prohibited by `REQ-TAG-003`).
- Implementing scope beyond Phase 1 (e.g. streaming integrations, cloud syncing, format transcoding).

**Done-definition.** The run ends successfully when the §9 evidence chain is complete and every claim in `intent.yaml` is active with a passing test. It ends acceptably at a §10 degraded terminal state, evidence collected and reported plainly. There is no third way to end.

## 6. Build sequence

1. **Pre-flight**: Verify Node.js (>= 18), npm, and git access. Confirm `csd-intent` is on PATH.
2. **Land the visual identity into `docs/`**:
   - Copy theme tokens from `.delivery/design.md` into `docs/brand.md`.

3. **Scaffold Project**:
   - Initialize package.json, TypeScript, Vite, Tailwind CSS with design tokens (`--radius: 0.75rem`, emerald primary `hsl(160, 84%, 39%)`, cream background `hsl(40, 33%, 97%)`, Nunito font).
   - Install Electron, `music-metadata`, `node-id3`, `lucide-react`, `@psa-department-of-engineering/vitest-intent`, `vitest`.
4. **Implement Core Services & Electron Main/Preload**:
   - Implement `audio-metadata.ts` (ID3v2 and Vorbis comments read/write, artwork extraction).
   - Implement `file-organizer.ts` (car naming pattern, multi-disc formatting, FAT32 sanitization).
   - Implement `library-scanner.ts` (MP3/FLAC ingestion, non-fatal corruption handling, library query engine).
   - Implement `playlist-exporter.ts` (M3U with CRLF line endings and relative paths).
   - Implement `sync-manager.ts` (volume detection, delta comparison, file copying, stale file identification).
   - Implement Electron main window, undockable player window, and ContextBridge preload IPC handlers.
5. **Implement UI Application & Web Shell**:
   - Implement Library table (sorting, multi-field search, track selection).
   - Implement Tag Editor (single-track & batch tag editing, embedded artwork viewer/uploader).
   - Implement Audio Player (mini-player, dedicated player view, queue, seek/skip/shuffle/repeat, output sink selector).
   - Implement Car Sync dialog (drive selector, scope picker, delta preview, stale file prune confirmation).
   - Implement Web fallback view (honest offline prerequisite notice, SHA-256 download links, SmartScreen guide).
6. **Intent Tests & Conformance**:
   - Implement test suite in `tests/` with `intent("INT-...", ...)` covering all 27 claims.
   - Run `npx vitest run` to ensure all tests pass.
   - Activate all claims in `intent.yaml` (`status: active`).
   - Run `csd-intent .` to audit and verify clean intent coverage.
7. **Adversarial Review** (fresh-eyes, `adversarial-review` skill):
   - Review built codebase for correctness, offline security, tag preservation, and car sync reliability. Fix any blockers.
8. **Build Distribution & Packaging**:
   - Build static web container (`Dockerfile`, nginx configuration).
   - Build portable Windows package and generate SHA-256 checksums.
